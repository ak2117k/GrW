# TDA-008 Tamper-Evident Audit Log — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the placeholder `AuditLog` into a tamper-evident, hash-chained, append-only log written by a single concurrency-safe `AuditService.append`, with chain verification and an ADMIN-only read/verify/export endpoint, and migrate the existing auth/mfa audit writers onto it.

**Architecture:** One global hash chain (`chainKey='global'`, partition-ready). `append(event)` runs in a `Serializable` transaction guarded by a per-chain `pg_advisory_xact_lock`: it reads the chain head, computes `hash = sha256(prevHash + canonicalize(payload))` with a contiguous `seq`, and inserts; a `@@unique([chainKey, seq])` backstops the race. `verifyChain` re-walks rows in `seq` order and pinpoints the first broken link. A `@Global AuditModule` exposes `AuditService`; an `@AdminOnly` controller lists/verifies/exports.

**Tech Stack:** NestJS 11, Prisma 6 (Postgres `td_saas`/`td_saas_test`), Node `crypto`, Jest 29.7 + ts-jest. RBAC from TDA-003 (`@AdminOnly`, `RolesGuard`, `@CurrentUser`). CLS/tenant from TDA-003 (`AuditLog` is NOT a tenant model → unscoped).

- **`append` is strict** (throws). Auth/mfa call sites keep their existing `try/catch` swallow (best-effort); orders/consent (later specs) call it transactionally. No row may ever be written with `hash === ''`.

- **Genesis:** `GENESIS_PREV_HASH = '0'.repeat(64)` is `prevHash` for `seq === 1`.
- **Taxonomy:** `AUTH_*` set is emitted by THIS spec (migrate existing writers). `CREDENTIAL_*`/`CONSENT_*`/`ORDER_*`/`AUTOTRADE_*` are *defined* here, emitted by TDA-005/009/011.

### Task 2: Schema delta + forward migration + backfill

**Files:**
- Modify: `prisma/schema.prisma` (`AuditLog` per spec §3.1).
- Create: `prisma/migrations/<ts>_tda008_audit_chain/migration.sql`.
- Create: `prisma/audit-backfill.ts`.

**Context:** Current `AuditLog` has `prevHash String?`, `hash String`, no `seq`/`chainKey`. Existing rows have `hash=''`, `prevHash=''`. The migration must be **forward-only** and survive a prod `prisma migrate deploy`, so the backfill that recomputes hashes is **two-phase**: add nullable `seq` + `chainKey` (DDL), backfill (JS), then tighten to `NOT NULL` + add `@@unique`.

- [ ] **Step 1: Edit `schema.prisma`** — apply the §3.1 block (`chainKey String @default("global")`, `seq BigInt`, `prevHash String`, `@@unique([chainKey, seq])`, `@@index([chainKey, seq])`; keep existing indexes + `@@map`).

- [ ] **Step 2: Generate the migration WITHOUT applying, then hand-edit for two-phase + backfill safety.** From repo root:
  `npx prisma migrate dev --name tda008_audit_chain --create-only` (`--create-only` writes the SQL but does not run it — lets us insert the backfill safely). Then edit `migration.sql` so the order is: (1) `ADD COLUMN "chainKey" TEXT NOT NULL DEFAULT 'global'`; (2) `ADD COLUMN "seq" BIGINT` (nullable for now); (3) leave `prevHash` nullable for now; (4) **do NOT** add the `@@unique`/`NOT NULL` yet — those come after backfill (Step 4). Add `CREATE INDEX … audit_logs_chainKey_seq_idx`.

- [ ] **Step 3: Write the backfill** `prisma/audit-backfill.ts` — idempotent: load all rows `orderBy [{createdAt:'asc'},{id:'asc'}]`; if every row already has a non-null `seq` and a non-empty `hash`, exit (idempotent re-run). Otherwise assign `seq=1..N`, `chainKey='global'`, recompute `prevHash`/`hash` via the **shared** `canonicalize`+`sha256` (import from `apps/api/src/common/audit/canonicalize`), and `update` each row. Row 1 `prevHash=GENESIS_PREV_HASH`. Run it: `DATABASE_URL=<td_saas> npx ts-node prisma/audit-backfill.ts`.

- [ ] **Step 4: Second forward migration to seal the chain** — `npx prisma migrate dev --name tda008_audit_chain_seal --create-only`, hand-edit to: `ALTER COLUMN "seq" SET NOT NULL`, `ALTER COLUMN "prevHash" SET NOT NULL`, `CREATE UNIQUE INDEX "audit_logs_chainKey_seq_key" ON "audit_logs"("chainKey","seq")`. Apply both migrations: `npx prisma migrate dev` (applies pending), then `npx prisma generate`.

- [ ] **Step 5: Verify** `npx prisma migrate status` is clean; `docker exec td-postgres psql -U postgres -d td_saas -c '\d audit_logs'` shows the new columns/indexes. **Do not** run on `td_saas_test` here — DB-backed tests apply migrations via their own setup / `prisma migrate deploy` against `DATABASE_URL_TEST`.
