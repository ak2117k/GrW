# MBM M0 — Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A training store of broker bars (NIFTY spot 1m at max depth + the §5.1.4 driver list) on the owner's Windows PC, rebuilt or topped up by one command, plus a prod job that exports OI / OI-wall / option-chain snapshots every night before the prunes delete them, pulled to the PC over scp.

**Architecture:** A new Python package `ai-engine/src/mbm/` (store, Angel + Yahoo history clients, scrip master, universe, probes, backfill, export import) driven by one CLI `ai-engine/scripts/mbm_data.py`. The prod export is a host-side bash script run by a systemd timer (same pattern as `grw-backup`), writing gzipped CSV to `/opt/grw/exports/`; the PC pulls with `ssh`/`scp` and folds the files into the same parquet store.

**Tech Stack:** Python 3.12, pandas, pyarrow (parquet), httpx, pyotp, pytest; bash + `docker exec psql \copy` + systemd on the VPS.

**Spec:** `docs/superpowers/specs/2026-10-18-market-behaviour-model-design.md` (§3, §5.1, §6 M0, §10.3, §10.7)

## Global Constraints

- Training store lives on the owner's PC, **outside the repo**. Default root `Path.home() / "grw-mbm"`, overridable by `--store` or env `MBM_STORE`. Never under `ai-engine/data/` and never committed.
- Parquet per series and interval, partitioned by month: `<root>/bars/<interval>/<series_id>/<YYYY-MM>.parquet` (month = IST calendar month). Series ids match `^[A-Z0-9_-]+$` (Windows-safe: no `:` `^` `=`).
- Bar schema (every bar file): `ts` (datetime64[ns, UTC], bar open), `open`, `high`, `low`, `close` (float64), `volume` (Int64), `oi` (Int64, nullable). Sorted by `ts`, unique on `ts`.
- Train only on broker-sourced bars (spec §3). Tick-built `candles_1m` is never read.
- Angel credentials come from `apps/api/.env` keys `ANGEL_ONE_API_KEY`, `ANGEL_ONE_CLIENT_ID`, `ANGEL_ONE_PASSWORD`, `ANGEL_ONE_TOTP_SECRET` (process env overrides the file). They are **never printed, logged, put in exception text, or written to the store**.
- Angel historical calls: ≥ 0.5 s gap between calls (respects the 350 ms historical gate and CLAUDE.md "max 10 req/sec"); 1m requests chunked at **29 days**; retry up to 4 times with 2 s, 4 s, 6 s back-off.
- Angel pulls run off-hours: refused Mon–Fri 09:00–15:45 IST unless `--allow-market-hours` (the PC logs in as the owner's same Angel user that prod uses).
- NIFTY spot token `99926000`, BANKNIFTY `99926009` (both NSE). Every other token is resolved from the Angel scrip master `https://margincalculator.angelbroking.com/OpenAPI_File/files/OpenAPIScripMaster.json`, never hardcoded.
- NIFTY driver list (spec §5.1.4, verbatim): heavyweights RELIANCE, HDFCBANK, ICICIBANK, INFY, TCS, BHARTIARTL, LT, ITC; BANKNIFTY; India VIX; USDINR (NSE currency futures via Angel, else the market-cues source); global cues US index futures, WTI/Brent, plus DXY / US 10-year.
- Market-cues source (verified in `apps/api/src/modules/market-cues/`): US indices/futures via **Yahoo v8 chart** (`https://query1.finance.yahoo.com/v8/finance/chart/{symbol}`, symbols `ES=F`, `NQ=F`); WTI `CL=F`, Brent `BZ=F` and USD/INR `INR=` come from a **CNBC quote snapshot with no history**. So all global-cue history in M0 uses Yahoo chart: `ES=F`, `NQ=F`, `CL=F`, `BZ=F`, `DX-Y.NYB`, `^TNX`, `INR=X`.
- Prod export: `/opt/grw/exports/<table>/<table>-<YYYY-MM-DD>.csv.gz` (IST session date), **30-day local retention**, not R2. No new public ports; PC pulls with the existing root SSH key.
- Actual prod prunes (verified, stricter than the spec's "45 days"): `option_chain_snapshots` 30 d at **02:00 IST** (`options-chain.service.ts:800`), `oi_snapshots` 30 d at **02:45 IST** (`market-hub.service.ts:248`), `oi_wall_snapshots` 45 d (`sentinel-runner.service.ts:51`). The export runs at **01:15 IST** and catches up the last 7 days, so one missed night loses nothing.
- Prisma `DateTime` columns are `timestamp` without zone holding UTC; exports name them `*_utc` and the importer parses them as UTC.
- New Python deps go in a new `ai-engine/requirements-mbm.txt` (`-r requirements-scorer.txt`, `pyarrow>=17`, `pyotp>=2.9`); the scorer container's `requirements-scorer.txt` is untouched.
- Commits: explicit pathspecs only (`git commit -- <paths>`), conventional-commit messages ending with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Why a host systemd timer for the export, not a Nest `@Cron`

The repo has ~47 `@nestjs/schedule` jobs guarded by `CronLeaseService` (`CRON_LEASE_ENABLED`), but the export is chosen as a host job because: (1) it must write files to the VPS disk at `/opt/grw/exports`, which the API container does not mount; adding a volume to the trading process for a data-dump side job is the wrong coupling; (2) `psql \copy … TO STDOUT | gzip` streams with constant memory, whereas Prisma would materialise `chainJson` rows inside the 2 GB box's trading process; (3) the precedent for exactly this shape is `grw-backup.service/.timer` (`docker exec grw-postgres`, `Persistent=true` catch-up after reboot, Telegram alert on failure via `ExecStopPost`); (4) the cron lease exists to stop duplicate runs across API replicas, which a single host timer never has. Trade-off accepted: the export is not deployed by the API image; it is installed once with `systemctl` (Task 9).

## Review Focus

1. **Interrupted or throttled backfill, re-run** — a second `build` must fetch only from the last stored bar, add no duplicate rows, and retry the chunks that failed last time (Task 1 `test_write_bars_idempotent`; Task 6 `test_build_resumes_from_last_ts`, `test_failed_chunk_retried_next_run`).
2. **API error mistaken for "no data"** — an error chunk must never count as an empty month, never advance the depth probe, and must make `build` exit 1 naming the chunk; a holiday/pre-listing empty chunk is fine (Task 2 `test_error_chunk_reported_not_empty`, Task 5 `test_probe_error_is_unknown_not_empty`).
3. **Timezones** — Angel returns `+05:30`, Yahoo returns epoch seconds, psql exports are zone-less UTC; all land as UTC and daily bars group by IST session date (Task 1 `test_month_partition_uses_ist`, `test_derive_daily_ist_session`, Task 8 `test_import_parses_utc`).
4. **Export goes silent** — a missed night, a failed psql, or a weekday with zero rows must alert, not quietly write nothing; a half-written file must never look complete (Task 7 shell tests: catch-up, `.partial` cleanup, exit 4 on empty weekday).
5. **Running while prod trades** — the PC logs in as the same Angel user; Angel pulls during market hours are refused by default (Task 2 `test_market_hours_guard`).

### Task 5: Probes — history depth and expired futures

**Files:**
- Create: `ai-engine/src/mbm/probe.py`
- Test: `ai-engine/tests/mbm/test_probe.py`

**Interfaces:**
- Consumes: `AngelHistory.candles`, `fetch_history`, `Contract`, `SeriesSpec`, `update_manifest`
- Produces:
  - `@dataclass DepthResult(series_id: str, interval: str, earliest: date | None, status: Literal["ok","none","unknown"], calls: int, note: str = "")`
  - `probe_depth(series_id: str, interval: str, has_data: Callable[[date], bool | None], today: date, max_years: int = 10) -> DepthResult` — `has_data(d)` checks a 5-calendar-day window starting at `d`; returns `None` on error. Algorithm: step back one year at a time from `today` until a window has no data (or `max_years`); then bisect by month between the last year with data and the first without; result = first month with data (day precision not needed). Any `None` answer stops the search and returns `status="unknown"` with the last confirmed date in `note` — an error is never treated as "no data".
  - `@dataclass ExpiredResult(symbol: str, exch_seg: str, expiry: date, token: str, bars: int, status: Literal["served","empty","error"], message: str = "")`
  - `probe_expired(client: AngelHistory, contracts: list[Contract]) -> list[ExpiredResult]` — one 1m request per contract for `[expiry-10d, expiry]`.
  - `expired_candidates(meta_dir: Path, names: list[str], today: date, extra_csv: Path | None = None, db_url: str | None = None) -> list[Contract]` — union of: contracts in older scrip-master snapshots (Task 3) with expiry < today; rows of `--expired-tokens` CSV (`symbol,token,exch_seg,expiry`); and, if `db_url` is given, `SELECT symbol, token, exchange, expiry FROM instruments WHERE expiry < now() AND symbol LIKE '<NAME>%FUT'` (read-only; intended for the owner's local DB, never prod). Up to the 3 most recent expiries per name.
  - `write_probe_report(meta_dir: Path, depth: list[DepthResult], expired: list[ExpiredResult], run_date: date) -> Path` — writes `probes-<date>.json` and `probes-<date>.md` (a table per probe kind) and records each `earliest` in the manifest as `depth_earliest`.
