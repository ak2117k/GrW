# AI Setups Implementation Plan (paper)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a verified channel claim ("Dabur breakout", CONFIRMED) into an AI-built option setup or a reasoned NO_TRADE, show it to the owner, paper-trade it on underlying levels, and grade it nightly — the evidence for going live later.

**Architecture:** A new `ai-setups` module. The message reader gains a stock quote block so stock claims are checkable. A reading with a CONFIRMED tradeable claim enqueues a setup job; a setup packet (daily/15m bars, option chain, news, channel record) is built time-boxed; Opus returns strict JSON; code checks (anti-chase, R:R, liquidity, SL-fits-ceiling) can downgrade to NO_TRADE; a SETUP becomes a pending entry watched on the underlying's price, filled as a PAPER option trade through the entry-engine paper path, and exited by its own underlying SL/targets plus the normal paper management. Live trading is a later plan (needs ≥ 20 graded setups + owner OK).

**Tech Stack:** NestJS 10, Prisma, Jest, React (web), Vertex Claude via the ai-gateway agents.

**Spec:** `docs/superpowers/specs/2026-11-25-ai-setup-design.md` (incl. "Settled after the builder check").

## Global Constraints

- `AI_SETUPS=off|paper` (default off). This plan has **no live mode**; nothing here may reach broker order code (paper path only: `isPaper: true`).
- v1: option **BUYS** only (index, stock, MCX options), 1 lot, **intraday only** (validUntil ≤ 15:15 IST NSE / 23:00 MCX; nothing carried overnight).
- Levels (entry zone/trigger, SL, targets) are **underlying prices**; the setup names the option (strike, expiry).
- Code checks, all mandatory: SL on the protective side; reward:risk to T1 ≥ 1.2; BREAKOUT_TRIGGER / MARKET_NOW entry within 1.5 × 15m ATR of a cited level that exists in the packet; LIMIT_PULLBACK entries below current price for a bullish view (above for bearish); option spread ≤ 2% and OI ≥ `AI_SETUP_MIN_OI` (default 500 contracts' worth — builder sets per exchange); SL distance × |delta| × lot ≤ the class ceiling (Plan 1 `classCeilingFor`, else ₹2,000). Any failure → NO_TRADE with the failed check named.
- No setup when: the post is a CALL; a signal trade or another setup is open/pending on the same underlying; 3 AI setups already today; the underlying had a setup in the last 30 min.
- Every cited evidence value must exist in the packet (same rule as the reader, "every" not "some").
- Model: Opus (`AI_SETUP_MODEL`, default `claude-opus-5`), effort high, job `setup.build` on the reading agent, concurrency 2.
- Never decide on 1m bars; 15m smallest. Broker session is scarce: setup packet builds concurrency 2, time box `AI_SETUP_PACKET_MS` 8000.
- Run API tests `cd apps/api && npx jest <pattern>`, web `cd apps/web && npx vitest run <path>`; tsc: no new errors in touched files.
- Explicit pathspec commits ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push; deploy after 15:35 IST only.

## Review Focus

1. A burst of confirmed claims (5 in a minute) never produces more than the daily cap or two setups on one underlying.
2. A pending entry whose validUntil passes, or whose underlying gaps through the SL before entry, never fills.
3. Paper exits fire on the underlying SL/targets even if the option has no fresh tick; and never twice.
4. Restart while a setup is pending or open: state recovers from the DB (no lost or duplicated paper trade).
5. Missing data (no chain, no news, no quote) gives NO_TRADE with the reason — never a setup built on absent numbers.

### Task 5: Pending entry and paper exits on the underlying

**Files:** Create `ai-setups/services/setup-watch.service.ts` + spec; use `EntryEnginePaperService.open` (entry-engine) with `brand: { strategy: 'AI_SETUP', source: 'ai-setup', tags: ['ai-setup', 'setup:<id>'], label: 'AI setup' }` and `planEntry` from signal-trader for the option plan; close via `TradeExecutionService.closeTrade` (as the paper watch does).
**Produces:** every 5 s for PENDING/FILLED setups (≤ 3/day so cheap): underlying LTP from the market hub live feed when the token is live, else `MarketQuoteResolver` (one batch per pass). PENDING: entry condition met (LIMIT_PULLBACK: LTP inside zone; BREAKOUT_TRIGGER: a 15m close beyond the trigger) and before validUntil and SL not already crossed → open the paper option trade (1 lot, ATM-or-named strike from the setup) → FILLED with tradeId. validUntil passed → EXPIRED. FILLED: underlying crosses SL → close `AI_SETUP_SL`; T1 → move SL to entry underlying level (trail), last target → close `AI_SETUP_TARGET`; validUntil / session end → close `AI_SETUP_TIME`; if the trade was closed elsewhere (paper sentinel / floor), mark EXITED with that reason. State only from the DB on each pass (restart-safe); a row update guards against double open/close (conditional updateMany on status).
